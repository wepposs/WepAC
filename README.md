# WepAC — самообучаемый ИИ-античит для Minecraft

Гибридный античит для серверов **Spigot/Paper 1.21+** (собран и проверен под 1.21.11, Java 17+). Работает на связке:

1. **Эвристические проверки** — детерминированные правила (Fly, Reach, AutoClicker и т.д.), дают VL и наказания.
2. **Самообучаемая нейросеть** — маленький MLP (18 → 16 → 8 → 1) на чистой Java без зависимостей. Учится онлайн на вашем сервере и:
   - оценивает вероятность чита для каждого игрока (0–100%),
   - **адаптирует пороги проверок** под каждого игрока (подозрительным — строже, проверенным — мягче),
   - выдаёт отдельные алерты для персонала при высокой вероятности.

Веса модели, статистика нормализации и буфер обучающих примеров **сохраняются на диск** (`plugins/WepAC/ai/model.bin`) — обучение переживает перезапуски сервера.

---

## Как учится ИИ (цикл самообучения)

```
телеметрия игрока ──► 18 признаков ──► нормализация (популяционная статистика)
      (клики, скорость,       │
       полёт, ротация,        ▼
       интервалы блоков)   нейросеть ──► P(читер) ──► алерты + адаптивные пороги
                              ▲
                              │ обучение (mini-batch SGD, async, каждые 60с)
        ┌─────────────────────┴─────────────────────┐
        │ источники меток:                          │
        │  • наказание (кик/бан) проверкой → читер  │
        │  • /ac label <игрок> <cheater|legit>      │
        │  • 20+ минут чистой игры без VL → честный │
        └────────────────────────────────────────────┘
```

Признаки (18): CPS, стандартное отклонение и минимум интервалов кликов (роботическая ровность), мин./сред./макс. скорость, доля времени в воздухе, доля «подъёма» в воздухе, атак в секунду, средний reach, интервалы ломания/установки блоков, скорости поворота yaw/pitch, пинг, средний угол до цели в момент удара, средний заряд кулдауна 1.9+ при ударах, доля ударов в воздухе (крит-ритм), частота реверсов pitch (silent-ротации). Combat-признаки учитываются только если с последнего удара прошло < 15 сек — часовой давности бой не «фонит» в профиль билдера.

### Обучение на живом PvP (`CombatProfiler`)

Античит наблюдает за настоящими PvP-боевыми сессиями (игрок бьёт игрока) и **учится тому, как сражаются честные игроки именно на вашем сервере**:

- каждый PvP-удар продлевает сессию обоим бойцам; телеметрия (18 признаков) снапшотится прямо во время боя каждые 2.5 сек;
- когда бой закончился (10 сек без PvP-ударов), игрок может сдать снапшот в обучающий буфер с меткой «честный» — но только через **тройной фильтр**: ноль активных VL, досье CLEAN (не на учёте/в розыске), ИИ-вероятность < 0.35. Сессия должна быть настоящим боем: ≥ 15 сек и ≥ 20 ударов;
- донорство ограничено: не чаще 3 сэмплов в час на игрока;
- **защита от отравления**: каждый сэмпл помечен UUID донора. Если «честный» донор позже наказывается (кик/бан) — все его прежние честные сэмплы автоматически вычищаются из буфера. Читер, временно выглядевший чистым, не может навсегда испортить модель.

Так модель постоянно подстраивается под локальную норму: агрессивный PvP-стиль вашего сервера (высокий CPS, резкие доводки) со временем перестаёт выглядеть подозрительно, а отклонения от него — наоборот.

Чем дольше сервер работает, тем больше данных → тем точнее модель. Первую неделю рекомендуется держать `ai.punish-by-ai: false` (наказания только по правилам), а ИИ использовать как детектор и адаптивный усилитель.

## Архитектура: три слоя детекта

1. **Пакетный слой (без внешних зависимостей).** `PacketSniffer` инжектит `ChannelDuplexHandler` напрямую в netty-pipeline каждого игрока (та же техника, что у ProtocolLib, но нулевые зависимости). Видит настоящие move-пакеты клиента: их частоту (Timer), пропажу потока (Blink), флаг onGround (GroundSpoof → Criticals), невозможные значения (BadPackets: pitch > 90°, NaN/Inf координаты). Координаты каждого пакета уходят в ограниченную очередь, которую `PacketPhysics` разбирает попакетно на главном потоке (слой 2). Из netty-потока — только volatile-записи и offer в очередь, вся оценка — на главном потоке; рефлективное чтение полей пакетов закэшировано.
2. **Симуляция физики, два уровня точности (Grim-лайт).** Пока игрок в воздухе, вертикальная скорость обязана следовать `vy = (vy - 0.08) * 0.98` за тик.
   - **Попакетный уровень (PacketFly, 20 Гц).** `PacketPhysics` обрабатывает каждый move-пакет из netty-очереди и сверяет его dy с предсказанием физики от предыдущего пакета — без усреднения по окнам. Расхождение копится; 0.35 блока лишней высоты = overflow-событие, два события за 3 сек = флаг. Внешние импульсы (взрыв, слим-батут, поршень) распознаются и переанкеривают симуляцию, НЕ обнуляя накопленный заряд — «отмыть» divergence одним большим пакетом нельзя. Отдача сети (burst flush) и обрывы потока (>500мс) молча ресинкаются. Чистое ядро симуляции (`Sim`) не зависит от Bukkit и покрыто юнит-тестами (см. «Тесты»).
   - **Оконный уровень (4 Гц).** Монитор интегрирует ожидаемое смещение на каждом 5-тиковом окне и копит расхождение (порог 0.75 блока) — второй эшелон для тех же glide/slow-fall/подъёмов. Все скорости нормализуются по **реально прошедшему времени**, а не по фиксированным 5 тикам: просадки TPS больше не завышают скорости и не дают ложных флагов. Отсюда же Step/LongJump/WaterWalk/ElytraFly — детекты по физическим пределам, а не по «подозрительным» числам.
3. **Поведенческий слой + ИИ.** 30 событийных проверок, ансамбль KillAura из 13 детекторов и самообучающаяся нейросеть (см. выше).

Reach v2: для каждого игрока ведётся история позиций 20 Гц (2 секунды). При ударе дистанция измеряется до ВСЕХ позиций жертвы в окне, которое атакующий мог видеть (его пинг + пинг жертвы/2 + 150мс, кап 600мс), берётся минимум. Это убирает классические FP на высоком пинге и не даёт читу бить «туда, где жертва была на экране».

| Движение | **AirJump** | Двойной прыжок: внезапный рывок вверх в воздухе (легальный прыжок всегда начинается с земли, гравитация монотонно гасит vy) |

| Движение | **NoSlow** | Полная скорость (~0.12+ б/тик) во время использования предмета — ваниль замедляет до ~20% |
| Движение | **WaterWalk** | Аномальная скорость в воде (WaterSpeed-модули читов); Depth Strider и Dolphins Grace учитываются |
| Движение | **ElytraFly** | Набор высоты на элитрах без фейерверков/riptide (физика элитр так не умеет) |
| Движение | **AirStuck** | Зависание неподвижно в воздухе (модуль AirStuck из чит-клиентов) |
| Движение | **LongJump** | Горизонтальные бёрсты в воздухе > 0.55 б/тик (физика спринт-прыжка ~0.35) |
| Движение | **BoatFly** | Лодка не умеет летать: зависание/подъём/скорость вне воды с физическими лимитами по поверхности (лёд 1.8, вода 0.55, земля 0.35 б/тик). Подъём на баллистической дуге (высокая горизонталь) — не сигнал; grace только на реальные запуски (\|v\|>2). Наказание — **кик** на первом подтверждённом флаге, бан за рецидив через систему учёта |
| Движение | **NoWeb** | Движение сквозь паутину/ягодные кусты со скоростью ходьбы (ваниль ползёт ~0.05 б/тик) |
| Движение | **ElytraFly** | (1) набор высоты без фейерверков; (2) скорость > 3.2 б/тик без бустов (терминальная ~2.7) |
| Пакеты | **Timer** | Ускорение игрового времени: > 20.5 move-пакета/сек устойчиво 2.5+ сек (ваниль шлёт ровно 20; дробный кап ловит даже 1.05×). Высокий пинг больше не полное исключение — для него требуется 5с устойчивого превышения (бёрсты сбрасывают счётчик сами) |
| Пакеты | **Blink** | Поток пакетов остановлен > 2 сек, хотя игрок онлайн, + **micro-blink**: пауза 0.5–2с, после которой первый пакет приходит дальше, чем любая ванильная скорость могла бы унести за время молчания |
| Пакеты | **PacketFly** | Попакетная (20 Гц) симуляция гравитации: каждый dy move-пакета сверяется с `vy = (vy-0.08)*0.98`; 0.35 блока лишней высоты = overflow, 2 overflow за 3с = флаг. Ловит glide/hover/slow-fall/постепенный подъём и air-jump бёрсты быстрее и точнее оконного уровня; внешние импульсы (взрыв/слим/поршень) переанкериваются без обнуления заряда |
| Пакеты | **BadPackets** | Невозможные значения в пакетах (pitch > 90°, NaN/Inf координаты) |
| Пакеты | **GroundSpoof** | Клиент утверждает onGround=true, а серверная физика говорит «в воздухе» — корневой сигнал пакетных критов и NoFall-байпасов |
| Бой | **Criticals** | Два сигнала: (1) пакетный onGround=true во время атаки в воздухе — принудительные криты; (2) **CritRhythm** — 95%+ PvP-ударов в воздухе с метрономным интервалом (stddev < 60мс): роботизированный крит-спам, человек в бою сбивается с ритма |
| Бой | **Velocity (Anti-KB)** | Сервер знает, какой нокбек он применил. Считается **проекция** движения за 700мс окна **на направление нокбека** (спринт-отход больше не «съедает» нокбек на бумаге), < 35% ожидаемого = поглощение (флагманский модуль CatLean забирает 85–90%). Щит, вода, телепорт в окне и **стена на пути** (raycast) исключены |
| Бой | **Reach** | Lag-компенсированный v2: история позиций жертвы 20 Гц, замер по всему окну видимости атакующего (пинг + 150мс, кап 600мс) — честные хиты «в догонку» проходят, чит-дистанция нет |
| Бой | **AutoClicker** | CPS > 18 и «роботическая» ровность интервалов (stddev < 12мс на 45+ кликах) |
| Бой | **KillAura** | Ансамбль из 13 детекторов с буферами и **голосованием сигналов**: полный флаг (severity 3–4) требует 2+ независимых детекторов за 5с; одиночный сигнал даёт лишь информационный VL 1 — случайный эпизод элитного PvP больше не дозревает до кика. Детекторы: частота (**только атаки с зарядом ≥0.4** — честный джиттер 15–20 CPS не флагует), удар вне FOV (>75°), snap-aim (≤200мс), **GCD pitch И yaw** (float-safe Евклид с относительным допуском 7% — на симуляции честной мыши FP 0.17%, на raw-дублях детект 99%; Bedrock-игроки через Floodgate исключены), метрономный пейсинг (stddev < 25мс), NoSwing, aim-lock (stddev < 0.5°), multi-target (**только игроки** — sweep по мобам на фермах легитимен), **PerfectHits** (80%+ PvP-ударов в 2.5° от прицела), **CooldownLock** (1.9+: charge ≈ 1.0 с нулевой дисперсией — только по PvP, фулл-зарядный фарм мобов легитимен), **GUI-атаки** (удар с открытым контейнером — ванильно невозможен) |
| Блоки | **FastBreak** | Мгновенная ломка твёрдых блоков (hardness ≥ 1.0, без Haste; Efficiency V на камне исключён) + **Nuker-радиус**: ломка дальше 4.75 блока от глаз |
| Блоки | **FastPlace** | Установка блоков быстрее 14/сек |
| Блоки | **Scaffold** | Блок под ноги на ходу, глядя вперёд (pitch < 20°). Сигнал **информационный** (severity 1): god-bridge — легитимная ванильная техника с той же сигнатурой; эскалация только через устойчивый VL и кросс-чеки |
| Игрок | **FastRegen** | Регенерация чаще ванильной (событие отменяется). Ванильная saturated-регенерация (еда до насыщения, 1 HP/500мс) и peaceful-реген оцениваются по отдельному порогу 400мс — честные игроки не наказываются; сигнатура хака (50–150мс) ловится |
| Игрок | **FastEat** | Поедание/питьё быстрее ~1600мс (dried kelp исключён; событие отменяется — читер не получает еду) |
| Игрок | **InventoryMove** | Поворот камеры > 2° с открытым GUI — в ванили мышь захвачена интерфейсом |
| Игрок | **ChestStealer** | > 14 кликов/сек по контейнеру 1.2+ сек (человеческий shift-спам ~8-10) |
| Игрок | **Xray** | Статистический: > 12 алмазных/изумрудных руд и древних обломков на 1000 камня (легитная добыча ~0.5-1.5) при минимум 20 ценных руд; окно 800+ камня, консервативные пороги |
| Движение | **SilentRot** | Silent-ротации (silent scaffold/aura): серверный pitch И yaw снапают к блоку/цели и обратно. Считаются только реверсы, **скоррелированные с действием** (≤250мс после атаки/установки/использования) — это и есть сигнатура silent-snap; честные боевые флики между целями не скоррелированы и не считаются |
| Бой | **FastBow** | Выстрел из лука с полной силой быстрее 300мс (ваниль: ~1100мс; арбалеты с Quick Charge исключены) |
| ИИ | **AI** | Прямое наказание по вероятности модели (выключено по умолчанию) |

Каждая проверка отключаема и настраивается в `config.yml` (`checks.<имя>`).

## Установка

1. Скопируйте `target/WepAC-1.0.0.jar` в папку `plugins/` сервера.
2. Запустите сервер — конфигурация создастся в `plugins/WepAC/`.
3. Выдайте staff разрешение `wepac.alerts`, админам — `wepac.admin`.
4. Для стадий наказания с `tempban` нужен плагин наказаний (EssentialsX / CMI / LiteBans и т.п.) — на голом Spigot есть только `kick`/`ban`. Если команда наказания не выполнилась, WepAC пишет явный warning в консоль («Punishment command was NOT executed»), так что тихих «наказаний без наказания» не бывает.

Требования: Spigot/Paper 1.21.x, Java 17+ (на другой версии плагин отключится сам с явным сообщением). **Рекомендуется Paper**: на Spigot-маппингах пакетный слой деградирует (в логе при старте печатается матрица способностей «Packet layer probe: position/rotation/onGround», а нерезолвящиеся поля дают явный warning) — PacketFly/GroundSpoof/пакетные Criticals там могут быть неактивны. **Folia не поддерживается** (`folia-supported: false`, при загрузке на Folia плагин отказывается стартовать).

## Команды (алиасы: `/ac`, `/wac`)

| Команда | Описание |
|---|---|
| `/ac info <игрок>` | VL по проверкам, пинг, вероятность ИИ, обученный профиль поведения |
| `/ac alerts` | Вкл/выкл алерты для себя |
| `/ac label <игрок> <cheater\|legit>` | **Разметка для обучения ИИ** — добавьте пример в обучающий буфер. `legit` дополнительно **отзывает** все «читерские» сэмплы игрока (например, от ложного кика) — отравление модели обратимо |
| `/ac resetvl <игрок>` | Обнулить VL игрока, включая сохранённые в `vl.yml`, его «читерские» ИИ-сэмплы и ИИ-вероятность (VL не вернётся после релогина) |
| `/ac rehabilitate <игрок>` | **Полная отмена ложного наказания**: resetvl + снятие с полицейского учёта (пороги, анонсы) + анонс стаффу |
| `/ac record <игрок>` | Досье «полиции»: статус (чист/на учёте/в розыске), кики, баны, score поведения, история страйков |
| `/ac record <игрок> <watch\|wanted\|clear>` | Ручное управление учётом |
| `/ac ai status` | Размер буфера, счётчики классов, раунды обучения, ошибка |
| `/ac ai save` | Сохранить модель на диск |
| `/ac ai reset confirm` | Сбросить модель и буфер (необратимо, требует подтверждения) |
| `/ac reload` | Перезагрузить конфиг |

Разрешения: `wepac.admin` (команды), `wepac.alerts` (оповещения), `wepac.bypass` (не проверять — выдавайте билдерам и для ивент-миров).

## Наказательства

Стадии в `config.yml` (`punishments`): по росту VL — алерт → кик → темпбан. Команды выполняются от консоли, плейсхолдеры `%player%`, `%check%`, `%vl%`. Подтверждённое наказание автоматически уходит в обучающую выборку ИИ как метка «читер» (с UUID владельца — `/ac label <игрок> legit` отзывает эти сэмплы, если кик оказался ложным). Не выполнившаяся команда наказания (нет плагина) логируется явным warning'ом. Confirm-гейт применяется ко всем командам, чей глагол НЕ входит в `confirm.safe-commands` — неизвестные алиасы (`vban`, `sanction`) по умолчанию считаются жёсткими и без подтверждения не выполняются.

### Кик только когда убедился (`confirm`)

Кик/бан не выполняется, пока вердикт не подтверждён **любым** из способов:
- 2+ разных проверки имеют активные VL (игрок «фонит» по нескольким фронтам), или
- одна проверка превысила свой порог в 1.5+ раза (запредельная уверенность), или
- вероятность ИИ ≥ 97%.

Пока подтверждения нет — стадия **откладывается** и автоматически повторяется при каждом новом VL, а персонал видит `[вердикт не окончательный] ... наказание отложено`. Честный игрок с одним случайным флагом никогда не будет кикнут.

### Полицейский учёт (`record`)

Как постановка на учёт в полиции; база хранится в `records.yml` и переживает рестарты:

1. **Первый подтверждённый кик** → игрок **СТАВИТСЯ НА УЧЁТ** (`WATCH`): пороги всех проверок для него урезаются до 0.6×, каждый алерт получает тег `[НА УЧЁТЕ]`, при каждом входе модераторам объявляется, что пришёл поднадзорный.
2. **Повторный страйк на учёте** → античит проводит **полную проверку поведения**: строит досье (score = разные проверки×20 + суммарный VL×0.5 + ИИ×40 + страйки×15) и показывает его персоналу.
3. **score ≥ 100** → статус **В РОЗЫСКЕ** (`WANTED`), автобан (7 дней, настраивается `record.ban-command`), и в стафф-консоль **орётся** rage-сообщение — 3 раза подряд, текст настраивается в `record.rage-message`.
4. **score < 100** → автобана нет, но античит «очень-очень жалуется»: то же rage-сообщение с пометкой, чего не хватило до автобана — решение за модератором.
5. Каждый новый страйк игрока в розыске → снова крик в консоль. Пороги для «розыскных» ещё строже (0.4×).

Учёт не вечен: статус WATCH автоматически истекает до CLEAN через `record.expire-days` (30) без новых страйков — единственная ошибка больше не означает пожизненно ужесточённые пороги. WANTED снимается только вручную. Ручное управление: `/ac record <игрок>` (досье) и `/ac record <игрок> <watch|wanted|clear>`.

### Детектор клиента (`client-detect`)

При входе каждый клиент сам объявляет себя серверу в пакете `minecraft:brand` («vanilla», «fabric», «lunarclient», а чит-клиенты — своими брендами). **С 1.20.2 бренд приходит в configuration-фазе**, куда play-phase messenger не заглядывает — WepAC хукает Paper-событие `PlayerClientBrandEvent` через reflection (без compile-time зависимости), а на не-Paper сборках честно пишет warning и включает самотест: если после 10 входов не получено ни одного бренда, в лог уходит «Client detection INACTIVE». Вердикты:

- **CHEAT** — бренд совпал со списком `cheat-brands` (RockStar, Wurst, Impact, Meteor, LiquidBounce, RusherHack и др.). По умолчанию (`ban-on-brand: false`) это **не бан, а максимальная слежка**: игрок ставится НА УЧЁТ, персонал получает громкий алерт с рекомендацией проверить поведение до ручнего бана. Причина: бренд самодекларируется, и модпак может случайно collide с записью списка — слежка обратима, бан нет. С `ban-on-brand: true` совпадение приводит к мгновенному бану (`client-detect.ban-command`) с записью «В РОЗЫСК» — включайте, когда доверяете списку под свою аудиторию. Обобщённые английские слова (ghost, wave, delta, energy, peak, solar, expensive) вынесены из чит-списка в `watch-brands` — модпак «Delta Crafts» не должен страдать. **Отсутствие совпадения не доказывает ничего**: модифицированный клиент может назвать себя «vanilla» — таких берут поведенческие проверки и ИИ, а не детектор бренда.
- **SUSPICIOUS / UNKNOWN** — бренд из `watch-brands` или вообще незнакомый. Банить нельзя: это может быть редкий ванильный лаунчер. Игрок автоматически ставится **НА УЧЁТ** (пороги 0.6×, теги в алертах, анонсы входа), персонал видит `[КЛИЕНТ] ... зашёл с неизвестного клиента — слежка включена`.
- **KNOWN** — легальные клиенты из `known-brands` (Vanilla, Fabric, Forge, Quilt, OptiFine, Lunar, Badlion, TLauncher, HMCL, Prism...). Никаких наказаний — только доклад в стафф-консоль: `Steve → клиент: TLauncher`.

Сопоставление **защищено от коллизий** (правила в `matchBrand`, покрыты тестами): длинные бренды (8+ символов, «liquidbounce») ищутся подстрокой; 6–7 символов («meteor») — префиксом целого токена; короткие (≤5, «ghost», «delta», «wave») — только точным совпадением с целым токеном. Модпак «GhostlyCraft» или «Deltacraft» никогда не будет забанен за бренд «ghost»/«delta». Токены разделяются любыми не-буквенно-цифровыми символами.

Игроки с `wepac.bypass` (стафф, тестеры читов на полигоне) не банятся и не ставятся на учёт — бренд просто виден в `/ac info`.

Важно: ванильная сборка TLauncher шлёт бренд `vanilla` и неотличима от официальной — детектор честно помечает её Vanilla; пиратские мод-сборки (TL Mods и т.п.) обычно имеют собственные бренды и попадают в UNKNOWN → слежка.

## Защита честных игроков (guards)

Отдельная секция `guards` в конфиге:

- **`lag-guard`** — игрокам с пингом выше `lag-ping-threshold` (450мс) буферы подтверждения движений удваиваются: их телеметрия шумнее, и одиночные лаг-пики не могут накопить флаг.
- **`rollback`** — подтверждённый читер (Fly/WallClimb/AirJump/Phase, только после полного буфера) телепортируется на последнюю легальную позицию на земле. Чит не даёт преимущества, а честные игроки никогда не rubber-band'ятся: откат происходит только после подтверждения проверкой.
- **`/fly` и креатив** — игроки с `getAllowFlight()` (Essentials `/fly`, плагины регионов) полностью исключены из flight-семейства проверок.
- **Grace-периоды** — нокбек, PlayerVelocityEvent, телепорт (1.5с), респавн (3с), вход на сервер (3с), смена режима (2с).
- **Ванильная физика учтена**: элитры, riptide, левитация, slow falling, dolphins grace, speed-зелья, лёд/слизь/мёд, лестницы/лианы/scaffolding, кровати/сено/шерсть/порох (мягкое приземление), Depth Strider, Efficiency V (insta-mine), Haste, dried kelp (быстрое поедание), Quick Charge (арбалеты), sweep-атаки по мобам.
- **ИИ осторожен**: адаптивные пороги включаются только после 20+ наблюдений за игроком; `punish-by-ai` по умолчанию выключен; модель со старым набором признаков не грузится, а сбрасывается.
- **Защита от обратной петли ИИ**: вероятность для адаптивных порогов сглажена EMA (один шумный скоринг не ужесточает мгновенно все проверки), совокупное ужесточение (ИИ × полицейский учёт) имеет пол 0.5×, нормализатор признаков замораживается после 250k наблюдений (статистика не дрейфует месяцами), а игроки с подозрительной ИИ-вероятностью не могут сдавать «чистые» сэмплы в обучающий буфер.
- **Точность при лагах сервера**: оконные скорости MovementMonitor делятся на реально прошедшее время, а не на фиксированные 5 тиков — просадки TPS не завышают скорости; попакетный PacketFly ресинкается при обрывах потока и не флагует на сетевых бёрстах.
- **Буферы везде**: ни одна проверка не флагует с одного замера — нужны серии подтверждений.

## Заметки по ложным срабатываниям

- Движение проверяется **по серверной правде** (bounding-box'ы блоков), а не по пакетам клиента.
- Любая телепортация/нокбек/респавн дают grace-период (1.5–3 сек). Grace от **урона** выдаётся только на причины, реально дающие нокбек (удар, снаряд, взрыв, sonic boom): огонь/яд/визер не двигают игрока и иммунитет больше не дают — раньше поджог себя давал полную слепоту всех проверок движения. Грации на мили-нокбек укорочены до 0.7с, чтобы GroundSpoof/Criticals/PacketFly не слепли на весь размен ударами.
- Полёт на элитрах, зелья (Levitation, Slow Falling, Dolphins Grace, Speed), лианы, лёд, слизь, мёд, кровати, вода, **паутина, пухляк и ягодные кусты** (медленное погружение — легальная физика) исключены из соответствующих проверок.
- **VL переживают релогин**: нарушения и сработавшие стадии наказаний сохраняются в `vl.yml` на выходе и восстанавливаются на входе (истекают через 7 дней) — читер на VL 24/25 больше не обнуляется переподключением.
- **Алерты троттлятся**: не чаще 1 сообщения в секунду на игрока+проверку (`alerts.cooldown-ms`). На VL и наказания троттлинг не влияет — только на поток сообщений в стафф-чат.
- **Оговорка по элитному PvP**: Aim-lock (stddev угла < 0.5°) и PerfectHits (80%+ ударов в 2.5° от прицела) эпизодически достижимы топовыми игроками с идеальным crosshair placement на низком пинге. Буферы подтверждения (2–3 серии) делают одиночные эпизоды безопасными, но на турнирном сервере эти два детектора разумно ослабить в конфиге.
- **Оговорка по InventoryMove**: собственный инвентарь (E) не fires InventoryOpenEvent, поэтому покрытие работает по окну 500мс после каждого клика по своему инвентарю — эвристика, а не гарантия. Контейнеры (сундуки и т.п.) отслеживаются точно через события.
- ИИ-вероятность сама по себе **не банит** по умолчанию — только предупреждает staff и ужесточает пороги.
- Если на вашем режиме есть легитимная механика (костомные чары, атрибуты скорости) — поднимите `multiplier`/`threshold` нужной проверки или отключите её.

## Известные ограничения (честно)

- **Только Spigot/Paper 1.21.x.** На другой мажорной версии плагин отключится сам с понятным сообщением (fail-fast), а не упадёт в случайном месте. **Folia не поддерживается** (нет глобального главного потока) — при загрузке на Folia плагин отказывается стартовать.
- **Нет потиковой симуляции горизонтали и транзакций.** Вертикаль симулируется попакетно (PacketFly), но горизонтальное движение проверяется окнами 4Гц по константным лимитам с растущим списком исключений, а лаг-компенсация Reach — пинг-оконная, а не транзакционная (Grim-класс). Тонкие bypass-режимы, сидящие под лимитами окон, теоретически возможны — это архитектурный потолок текущей версии, см. дорожную карту.
- **Локальные файлы в сетях.** `vl.yml`, `records.yml`, `model.bin` живут на одном сервере: кикнутый на survival-1 игрок зайдёт чистым на survival-2. Для сетей нужен общий бэкенд (MySQL/Redis) — в дорожной карте.
- **Legacy и Bedrock гейтятся по месту.** 1.8-клиенты через ViaVersion (protocol ≤ 47) исключены из charge-детекторов (CooldownLock, rate-гейт считает все атаки), а ИИ-признак заряда для них нейтрален; **Bedrock/Floodgate** исключены из мышиных эвристик (GCD/пейсинг/CooldownLock/InventoryMove), но не из физики и reach. В `/ac info` такие игроки помечены `[1.8 protocol]` / `[Bedrock]`.
- **ИИ**: `lastErr` в `/ac ai status` — ошибка обучающего батча, не валидационная; holdout-выборки и early stopping нет. Обучающая loss — MSE (переход на binary cross-entropy с momentum в планах — он изменит динамику обучения и потребует перегенерации предобученной модели). Предобученные архетипы не закреплены как anchor-набор — при долгом онлайн-обучении возможен катастрофический forgetting архетипов. Бенчмарк RESULTS.md синтезирован одним генератором (см. шапку RESULTS.md).
- **Строки интерфейса частично на русском** (алерты учёта/клиентов, rage-message). Полная i18n через messages.yml — в дорожной карте; формат алертов проверок настраивается уже сейчас.
- `/ac reload` не перерегистрирует интервалы фоновых задач (decay/score/train) — они применяются после рестарта.

### Дорожная карта (порядок имеет значение)

1. **Полевая валидация (главное).** Рекордер телеметрии + `/ac dump <игрок>`, replay-харнесс прогона записанных сессий через чистую логику, корпус фикстур (реальные чит-клиенты + легитимные сценарии из чеклиста ниже), CI-гейт «ноль флагов на legit-корпусе». Без этого любой тюнинг порогов — на глаз.
2. **Пакетный движок Grim-класса.** Перехват `write()` в duplex-хендлере → исходящие ping/pong транзакции → точная карта «пакет → тик клиента» → потиковое предсказание позиции с коллизиями и горизонтальной физикой → setback'и пакетами вместо Bukkit-телепортов → семейство BadPackets порядка/состава пакетов (дешёвые и почти без FP).
3. **ИИ-математика.** BCE + momentum + L2, holdout 10% с AUC в логе раундов, anchor-подмес предобученных архетипов (20–30% батча), персистенция профилей, секвенционная модель по покадровым векторам.
4. **Экосистема.** MySQL/Redis для сетей, messages.yml (ru/en), bStats, Via-гейтинг 1.9+-проверок по protocol version, per-region отключения (WorldGuard hook), verbose-режим и paste-отчёты для разбора FP.

## Smoke-чеклист на живом сервере (перед боевым запуском)

Прогнать на тестовом 1.21.x сервере и записать результаты (это закрывает «Фазу 0» дорожной карты — без неё дальнейший тюнинг вслепую):

- [ ] В логе старта: «Packet layer probe ... position=true rotation=true onGround=true — all packet checks ACTIVE» (если нет — маппинг сервера не поддерживается, пакетный слой мёртв, в логе будет явный warning).
- [ ] В логе: «Client detector: Paper PlayerClientBrandEvent hooked» (на Paper) или warning про configuration-фазу (на Spigot); после 10+ входов НЕТ «Client detection INACTIVE».
- [ ] Стояние на голове другого игрока 10+ сек в лобби: ноль флагов Fly/GroundSpoof/AirStuck.

## Структура проекта

```
src/main/java/dev/weposs/wepac/
├── WepAC.java                  # главный класс, задачи скоринга/обучения
├── ai/                         # самообучаемое ядро
│   ├── NeuralNetwork.java      # MLP + backpropagation (чистая Java)
│   ├── AIBrain.java            # признаки, нормализация, скоринг, онлайн-обучение, персистентность
│   ├── FeatureVector.java      # 18 признаков поведения
│   ├── PlayerProfile.java      # персональный профиль (Welford)
│   └── TrainingSample.java
├── check/                      # базовый класс проверок, адаптивные пороги
├── checks/
│   ├── movement/               # MovementMonitor (4Гц телеметрия) + Fly/Speed/Jesus/NoFall/FastClimb
│   ├── combat/                 # Reach / AutoClicker / KillAura
│   └── block/                  # FastBreak / FastPlace / Scaffold / FastRegen
├── packet/                     # PacketSniffer (netty-инжект) + PacketPhysics (попакетная симуляция)
├── violation/  punish/  alert/ # VL-контур, наказания, оповещения staff
├── data/       listener/       # телеметрия (TelemetryCollector — всегда включён),
│                               # ViolationStore (VL переживают релогин), grace-периоды
├── command/                    # /ac
└── util/GroundUtil.java        # серверная проверка «на земле»
```
